# 本地升级中心 5 分钟联调清单

## 1. 适用范围
- 项目：HAO UIED 商业版
- 目标：在本地快速验证“升级中心页面可用、目录就绪、升级包识别、任务可发起”这 4 个关键环节
- 配套正式文档：`docs/API/后台升级中心SOP-2026-04-04.md`
- 生效日期：2026-04-05

## 2. 本地联调目标
5 分钟内至少确认以下结果：
- 后台能打开 `系统设置 -> 升级中心`
- 概览区能正确识别目录状态
- 升级包列表能读到本地测试包
- 点击“开始升级”时，能正确进入任务审计链路

说明：
- 如果你只想验证页面和接口联通，不必先跑真实升级。
- 如果你要验证完整升级闭环，再执行第 5 节的“启动测试任务”。

## 3. 前置条件
1. 本地管理后台可访问：`http://localhost:5173`
2. 本地后端可访问：`http://127.0.0.1:8002`
3. 已登录超级管理员账号
4. 本机已有一个可用的升级包（`.tgz` 或 `.tar.gz`）

## 4. 本地最小准备
### 4.1 创建本地测试目录
在 Mac 终端执行：

```bash
BASE="/Users/tangxiaoda/Desktop/网站备份/HAO UIED/release/local-upgrade-test"
mkdir -p \
  "$BASE/packages/1.1.1" \
  "$BASE/backups" \
  "$BASE/tmp" \
  "$BASE/deploy/frontend" \
  "$BASE/deploy/admin" \
  "$BASE/deploy/backend"
```

### 4.2 放入测试升级包
把你的测试升级包放到：

```bash
$BASE/packages/1.1.1/
```

例如：

```bash
/Users/tangxiaoda/Desktop/网站备份/HAO UIED/release/local-upgrade-test/packages/1.1.1/uied-nav-1.1.1-release-bundle.tgz
```

### 4.3 计算升级包 SHA256

```bash
shasum -a 256 "/Users/tangxiaoda/Desktop/网站备份/HAO UIED/release/local-upgrade-test/packages/1.1.1/uied-nav-1.1.1-release-bundle.tgz"
```

记下输出的前 64 位哈希值，稍后填入后台。

## 5. 后台 5 分钟联调步骤
### 5.1 打开升级中心页面
访问：

- `http://localhost:5173/uied/system-setting/upgrade-center`

预期：
- 页面可正常打开
- 顶部能看到“升级中心概览”
- 未配置时会显示待处理项，而不是白屏或接口报错

### 5.2 保存一套本地测试配置
在“升级中心配置”中填写：

- 升级包目录：`/Users/tangxiaoda/Desktop/网站备份/HAO UIED/release/local-upgrade-test/packages`
- 备份目录：`/Users/tangxiaoda/Desktop/网站备份/HAO UIED/release/local-upgrade-test/backups`
- 临时目录：`/Users/tangxiaoda/Desktop/网站备份/HAO UIED/release/local-upgrade-test/tmp`
- 前台部署目录：`/Users/tangxiaoda/Desktop/网站备份/HAO UIED/release/local-upgrade-test/deploy/frontend`
- 后台静态目录：`/Users/tangxiaoda/Desktop/网站备份/HAO UIED/release/local-upgrade-test/deploy/admin`
- 后端部署目录：`/Users/tangxiaoda/Desktop/网站备份/HAO UIED/release/local-upgrade-test/deploy/backend`
- 健康检查地址：`http://127.0.0.1:8002/api/uied/license/public-status`
- 重启模式：`none`
- 二次确认口令：`UPGRADE`

点击“保存配置”。

预期：
- 顶部概览里的目录检查全部变成“目录可读写”
- 如果升级包目录里已有测试包，则“升级包数量”大于 `0`

### 5.3 刷新服务器升级包列表
点击“刷新升级包”。

预期：
- 列表里能看到你刚才放进去的 `.tgz` / `.tar.gz`
- 点击“使用此包”后，升级表单里的“升级包路径”会自动回填为相对路径

例如：

```text
1.1.1/uied-nav-1.1.1-release-bundle.tgz
```

### 5.4 检查概览区是否允许启动
预期：
- `当前版本` 显示当前系统版本号
- `是否可启动升级` 显示“可启动”
- `最近升级包` 能看到刚才的测试包

如果仍然显示“未就绪”，优先检查：
- 升级包目录里是否真的有包
- 目录是否写错成文件路径
- 部署目录是否不存在或不可写

### 5.5 启动一次本地测试任务
在“启动升级任务”里填写：

- 目标版本：例如 `v1.1.1-local-test`
- 升级包路径：使用列表自动回填值
- SHA256：使用第 4.3 节算出的值
- 二次确认口令：`UPGRADE`
- 超级管理员密码：当前登录管理员密码

然后点击“开始升级”。

预期：
- 页面提示“升级任务已启动”
- “升级任务审计”里新增一条记录
- 状态会进入 `pending / running / success` 其中之一

## 6. 本地联调成功标准
满足以下 4 条即可认为本地升级中心基本可用：
- 页面能打开，且概览接口返回正常
- 配置保存后，概览区能正确识别目录状态
- 升级包列表能读取并回填相对路径
- 启动任务时，不再被“尚未准备完成”拦截

## 7. 常见问题
### 7.1 页面能开，但一直提示“升级中心尚未准备完成”
优先检查：
- 升级包目录是否为空
- 升级包后缀是否为 `.tgz` 或 `.tar.gz`
- 配置保存后是否重新刷新过概览

### 7.2 任务启动时报 SHA256 校验失败
说明：
- 升级包文件和你填写的哈希值不一致

处理：
- 重新执行 `shasum -a 256 文件路径`
- 复制完整 64 位哈希值，不要带文件名

### 7.3 任务能创建，但执行失败
先看“升级任务审计”里的：
- 状态
- 阶段
- 错误信息
- 回滚状态

如果是本地联调，先确认：
- 你的测试包本身结构是否符合正式发包规范
- 测试部署目录是否可写
- 不要把部署目录指向当前开发源码目录

## 8. 本地联调注意事项
- 本地联调时，`前台部署目录 / 后台静态目录 / 后端部署目录` 不要直接填写生产目录。
- 也不要直接指向你当前正在开发的源码目录，否则升级脚本会改动当前工作副本。
- 本地联调推荐只验证“概览、读包、起任务、看日志”这条链路；真实升级闭环放到专用测试目录或测试服务器演练。
