# 宝塔升级不丢图片SOP（2026-04-14）

适用版本：`v1.1.1+`（已支持独立上传目录与升级保留 `uploads`）

## 1. 目标

- 用户升级源码后，历史上传图片/视频不丢失。
- 支持把上传目录放到项目外持久化目录。
- 升级中心执行后端包时默认保留 `app/public/uploads`。

## 2. 本次能力点

- 新增环境变量：`UIED_UPLOADS_ABS_DIR`
  - 可填绝对路径（推荐）。
  - 可填项目相对路径。
  - 可填 uploads 父目录或 uploads 目录本身，系统会自动归一到 `.../uploads`。
- 上传写入与读取统一走配置路径（素材上传、素材压缩、站点截图缓存）。
- 升级脚本 `uied_upgrade_runner.sh` 在部署 `backend-server.tgz` 时保留 `app/public/uploads`。

## 3. 宝塔目录建议

```text
/www/wwwroot/hao-uied/
  ├─ frontend/               # 前台静态站点
  ├─ admin/                  # 后台静态站点
  └─ server/                 # 后端服务目录（Egg）

/www/wwwroot/hao-uied-data/
  └─ uploads/                # 持久化上传目录（建议）
```

## 4. 首次部署（推荐）

1. 创建持久化目录并授权：
   - `mkdir -p /www/wwwroot/hao-uied-data/uploads`
   - `chown -R www:www /www/wwwroot/hao-uied-data/uploads`（按你的运行用户调整）
2. 在后端环境变量中配置：
   - `UIED_UPLOADS_ABS_DIR=/www/wwwroot/hao-uied-data/uploads`
3. 重启后端服务。
4. 在后台上传一张测试图，确认数据库 `uri` 为 `/public/uploads/...`，并能正常访问。

## 5. 升级流程（客户版）

1. 在升级中心上传你发布的升级包（bundle）。
2. 填写对应 `SHA256`。
3. 执行升级。
4. 升级完成后验证：
   - 随机打开 3-5 张历史素材 URL，确保可访问。
   - 新上传素材可写入并可访问。
   - 素材中心批量压缩可正常执行。

## 6. 回滚与兜底

- 升级脚本会自动备份前后端目录和数据库。
- 部署阶段失败会自动回滚。
- 建议你在发版前仍保留一次手工快照（项目目录 + 独立 uploads 目录）。

## 7. 常见问题

- 问：`UIED_UPLOADS_ABS_DIR` 不配置可以吗？
  - 可以。默认仍使用 `app/public/uploads`。
- 问：整包替换后图片会不会丢？
  - 新脚本下，后端升级阶段会保留 `app/public/uploads`；若你配置了独立上传目录，风险更低。
- 问：Nginx 需要改吗？
  - 只要你原有 `/public` 静态访问正常，通常无需额外改动。若你自定义了复杂反代，建议回归一次素材 URL 访问。
