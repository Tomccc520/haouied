# 1.0.1 版本开发记录（2026-03-07）

## 一、需求背景
- 用户反馈：后台「UIED导航 -> 网站管理」列表中的「前端查看/预览」按钮，在正式环境点击后仍跳转到本地测试地址。
- 目标：修复跳转地址来源，确保正式环境打开正式前端域名。

## 二、问题定位过程
1. 检索 `server/admin/src/views/uied/website/index.vue` 中前端跳转逻辑。
2. 发现页面内存在硬编码常量：
   - `const FRONTEND_BASE_URL = 'http://localhost:3003'`
3. 确认该值绕过了环境变量配置，导致生产环境仍指向本地地址。

## 三、修复方案
- 文件：`server/admin/src/views/uied/website/index.vue`
- 改动：
  - 新增 `getFrontendBaseUrl()`，统一从 `import.meta.env.VITE_FRONTEND_URL` 读取前端域名。
  - 当环境变量未配置时，回退到 `http://localhost:3003`（仅本地开发兜底）。
  - 保持草稿站点 `preview=1` 拼接逻辑不变。

## 四、回归检查
1. 校验 `server/admin/.env.production`：已存在 `VITE_FRONTEND_URL=https://hao.uied.cn`，可直接生效。
2. 代码层检查：前端跳转只变更了基础域名来源，不影响列表查询、编辑、删除等逻辑。

## 五、上线注意事项
1. 生产环境必须配置 `VITE_FRONTEND_URL` 为正式前端域名（不建议留空）。
2. 后台前端发版后，清理浏览器缓存再验证「前端查看」按钮。
3. 验证草稿站点链接仍带 `?preview=1`，发布站点不带该参数。

## 六、本次结论
- 根因已修复：网站管理页不再写死本地地址。
- 本次修复属于 1.0.1 版本启动阶段的首个线上可感知问题修复项。

## 七、追加修复（编辑已发布网站误判重复）
- 问题描述：
  - 编辑已发布网站时，即使没有改 URL，也可能被“重复网址校验”拦截，提示：`网站URL已存在（ID: xxxx）`。
- 根因：
  - 历史版本在编辑保存/发布时仍可能命中重复校验路径。
  - 当库内已有同主域名记录时，会导致编辑流程被误拦截，产生“无法保存”的错觉。
- 修复文件：
  - `server/server/app/service/uied/website.js`
  - `server/admin/src/views/uied/website/edit.vue`
- 修复策略：
  1. 后端编辑接口移除“编辑态 URL 重复拦截”，确保已发布网站可正常编辑保存/发布。
  2. 前端提交增加 `allowDuplicate: true` 兜底参数，兼容尚未升级到新后端时的线上环境。
  3. 重复提醒仅保留在“获取网站信息”动作中，不阻断编辑保存。
- 影响范围：
  - 仅影响“编辑网站”流程；
  - “新增网站”重复拦截逻辑保持不变。
