# 后台升级中心 SOP（宝塔版）

## 1. 适用范围
- 项目：HAO UIED 商业版
- 目标：在客户运营中实现“后台一键升级（自动备份 + 失败回滚）”
- 生效日期：2026-04-04

## 2. 菜单位置
- 后台路径：`系统设置 -> 升级中心`
- 访问路由：`/system-setting/upgrade-center`
- 兼容旧地址：`/uied/operation/upgrade-center`（自动重定向）

## 3. 首次启用（管理员）
1. 执行数据库补丁：`server/sql/patch_2026_0404_upgrade_center.sql`
2. 重启后端服务（PM2 或宝塔 Node 服务）
3. 重新登录后台
4. 打开“系统设置 -> 升级中心”确认页面可见

## 4. 升级包规范（必须）
升级主包（`.tgz` / `.tar.gz`）内建议包含：

- `frontend-site.tgz`
- `admin-static.tgz`
- `backend-server.tgz`
- `checksums.sha256`
- `db/upgrade.sql`（可选）
- `db/patch/*.sql`（可选）

说明：
- 有数据库结构/菜单数据变更时，必须提供 `upgrade.sql` 或 `db/patch/*.sql`。
- 无数据库变更也允许发包（脚本会自动跳过补丁）。

## 5. 客户后台升级步骤（标准）
1. 将升级包上传到服务器“升级包目录”（在升级中心配置页可见）。
2. 在“升级中心”选择/填写升级包路径。
3. 填写该升级包 `SHA256` 校验值。
4. 填写“二次确认口令”（默认 `UPGRADE`，可在配置页修改）。
5. 输入当前超级管理员密码。
6. 点击“开始升级（自动备份 + 自动回滚）”。
7. 在“升级任务审计”查看状态与日志，等待 `success`。

## 6. 安全机制（已落地）
- 仅超级管理员可访问升级中心接口。
- 发起升级必须校验管理员密码。
- 必须提供并校验升级包 `SHA256`。
- 校验压缩包条目路径，拦截 Zip Slip 越界覆盖风险。
- 升级前自动备份前端/后台/后端目录与数据库。
- 失败自动回滚代码与数据库。
- 全量审计：任务号、执行人、状态、日志、回滚结果、错误信息。

## 7. 失败处理
若任务状态为 `failed`：

1. 打开任务日志，查看失败阶段（`phase`）与错误信息。
2. 确认回滚状态：
   - `rollback_status=success`：业务可先恢复访问，再排查升级包问题。
   - `rollback_status=failed`：按备份路径手工恢复目录与数据库。
3. 修正升级包后重新发起新任务，不要复用已失败任务号。

## 8. 发版建议（研发）
- 每次版本发布都生成唯一升级包与 `SHA256`。
- 每次发版都做一次“升级 -> 失败回滚 -> 再升级”的演练。
- SQL 补丁必须幂等（可重复执行，不报错）。
- 尽量避免破坏性 DDL（删列/改列类型）直接进入客户升级流程。

## 9. 常见问题
- 问：首次安装要用升级中心吗？  
  答：不用。首次安装走安装向导或全量导入。

- 问：纯前端改动需要 SQL 吗？  
  答：一般不需要，脚本会自动跳过补丁。

- 问：客户可否不用超级管理员升级？  
  答：不建议。当前策略固定为超级管理员，降低被误操作与越权风险。
