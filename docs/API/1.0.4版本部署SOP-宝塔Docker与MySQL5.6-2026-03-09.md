# 1.0.4 版本部署 SOP（宝塔 Docker + MySQL 5.6）

## 1. 适用场景
- 后端 API 跑在 Docker 容器（容器名：`uied-api`）
- 服务器目录使用：`/www/wwwroot/hao.uied.cn/server-api`
- 数据库使用宝塔 MySQL（`3306`，目标兼容 `5.6+`）

## 2. 发布包与数据库文件
- 后端包：`release/1.0.4_20260309_190713/backend-server.tgz`
- 数据库（推荐，5.6/5.7/8.0 均可导入）：`release/1.0.4_20260309_190713/db/uied_nav_mysql56_compatible_1.0.4_20260309_190713.sql`
- 数据库（本地版，仅高版本更稳）：`release/1.0.4_20260309_190713/db/uied_nav_local_1.0.4_20260309_190713.sql`

说明：
- 生产建议统一使用 `mysql56_compatible` 文件，减少客户环境导入失败概率。
- `local` 文件常见在 MySQL 5.6 报索引长度错误（`1071/1089`）。

## 3. 后端部署步骤（标准流程）
```bash
# 0) 进入后端目录（宿主机）
cd /www/wwwroot/hao.uied.cn/server-api

# 1) 备份上传目录（强烈建议）
cp -a app/public/uploads app/public/uploads_bak_$(date +%F_%H%M%S) || true

# 2) 解压后端包（包内路径是 server/server，需要去掉两层）
tar -xzf /www/wwwroot/backend-server.tgz --strip-components=2 -C /www/wwwroot/hao.uied.cn/server-api

# 3) 生成生产配置文件（如果不存在）
cd /www/wwwroot/hao.uied.cn/server-api/config
cp -n config.prod.example.js config.prod.js
```

## 4. `config.prod.js` 关键配置（宝塔 MySQL）
```js
config.sequelize = {
  dialect: 'mysql',
  host: process.env.UIED_DB_HOST || '127.0.0.1',
  port: Number(process.env.UIED_DB_PORT || 3306),
  username: process.env.UIED_DB_USER || '你的数据库账号',
  password: process.env.UIED_DB_PASSWORD || '你的数据库密码',
  database: process.env.UIED_DB_NAME || '你的数据库名',
}
```

注意：
- 如果 MySQL 不在同一网络命名空间，`127.0.0.1` 可能不通，需要改成宿主机可达 IP。
- 容器模式优先建议用环境变量 `UIED_DB_*` 覆盖，便于多环境切换。

## 5. 导入数据库（MySQL 5.6 推荐）
```bash
# 先在宝塔创建空库（字符集 utf8）
# 然后导入兼容版 SQL：
mysql -u你的账号 -p 你的库名 < /www/wwwroot/uied_nav_mysql56_compatible_1.0.4_20260309_190713.sql
```

## 6. 重启后端容器并验证
```bash
# 重启容器
docker restart uied-api

# 查看日志
docker logs -n 150 uied-api

# 健康检查（宿主机）
curl -i http://127.0.0.1:8002/api/site-info
```

期望结果：
- `HTTP/1.1 200 OK`
- 返回 JSON，`code=0`

## 7. 为什么“没有 config.prod.js 也能跑”
常见原因：
- 容器里已经存在旧的 `config.prod.js`
- 启动命令带 `--env=prod`，同时数据库参数来自环境变量 `UIED_DB_*`
- 当前跑的是 `local` 配置（不推荐生产）

建议：
- 生产固定 `prod`，并显式维护 `config.prod.js` 或完整 `UIED_DB_*` 环境变量。

## 8. 容器路径与宿主机路径映射
- 宿主机：`/www/wwwroot/hao.uied.cn/server-api`
- 容器内：`/app`

检查命令：
```bash
docker inspect uied-api --format '{{range .Mounts}}{{println .Source " -> " .Destination}}{{end}}'
```

## 9. 常见问题速查

### 9.1 宿主机执行 npm 报错 `npm: command not found`
- 原因：Node 运行在容器内，不在宿主机 PATH。
- 处理：在容器内执行或仅重启容器（依赖未变更时）。

### 9.2 前端打开了但接口 502
- 原因：前端静态资源可访问，但后端 API 异常。
- 检查：`docker logs -n 200 uied-api` 与 `curl 127.0.0.1:8002/api/site-info`

### 9.3 数据导入报索引长度/前缀错误
- 原因：使用了非兼容版 SQL 导入 MySQL 5.6。
- 处理：改用 `uied_nav_mysql56_compatible_1.0.4_*.sql`。

## 10. 建议的生产启动方式（后续优化）
当前容器启动命令如包含 `npm install && egg-bin dev`，建议后续改为：
- 镜像构建阶段安装依赖
- 容器运行阶段使用稳定生产命令（非 `dev`）
- 配置全部走环境变量或 `config.prod.js`，避免漂移
