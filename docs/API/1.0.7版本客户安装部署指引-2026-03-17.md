# UIED-NAV 1.0.7 客户安装部署指引（Node + React + Egg）

> 适用版本：`1.0.7` 及以上
> 
> 目标：把“源码包”按可售卖主题的方式，稳定部署到客户服务器（宝塔优先）。

---

## 1. 部署形态选择（先选一种）

### A. 宝塔原生模式（推荐客户使用）
- MySQL：宝塔数据库（`5.6+`，推荐 `5.7+`）
- 后端：Node 20 运行 `server/server`
- 前端：`frontend/build` 静态站
- 后台：`server/admin/dist` 静态站
- Nginx：统一反向代理 `/api` 与 `/public`

### B. 容器模式（你当前常用）
- MySQL：Docker MySQL
- 后端：Docker `uied-api`
- 前端/后台：静态文件仍由 Nginx 托管

---

## 2. 服务器环境要求

- Node.js `20.x`
- MySQL `5.6.5+`（推荐 `5.7+`）
- Nginx `1.18+`
- Linux（CentOS / Ubuntu 均可）

---

## 3. 首次部署目录建议

```bash
/www/wwwroot/hao.uied.cn/
├── index.html                # 前端首页（frontend/build）
├── assets/                   # 前端静态资源
├── admin/                    # 后台前端（server/admin/dist）
└── server/                   # 后端 Egg 项目（server/server）
```

---

## 4. 数据库导入（宝塔 MySQL）

1. 新建数据库（字符集建议 `utf8`，排序规则 `utf8_general_ci`）。
2. 优先导入兼容包（5.6/5.7）：

```sql
uied_nav_mysql56_compatible_*.sql
```

3. 若你确认是 8.0 且无兼容问题，可导入标准包。

### 4.1 常见导入报错处理

- `ERROR 1071 Specified key was too long`
  - 说明使用了不兼容索引长度，换 5.6 兼容 SQL 包。
- `ERROR 1813 Tablespace exists`
  - 说明上次导入残留，先删库重建后再导入。
- `ERROR 1146 Table doesn't exist`
  - 通常是前面建表失败引起的连锁错误，先解决第一条报错再重导。

---

## 5. 后端配置（关键）

在后端目录（`server/config`）准备生产配置，核心是 MySQL 连接正确。

### 5.1 配置要点

- `dialect: 'mysql'`
- `host`: 宝塔本机建议 `localhost`
- `port`: `3306`
- `database/username/password`: 与宝塔数据库一致

### 5.2 启动模式说明

- 裸 Node：`NODE_ENV=prod npm run start`
- Docker：确保容器内 `--env=prod` 或 `EGG_SERVER_ENV=prod`

> 生产环境建议固定为 prod 配置，不要混用 local 配置。

## 6. 前端与后台部署

### 6.1 构建

```bash
# 前端
cd frontend
npm install
npm run build

# 后台
cd ../server/admin
npm install
npm run build
```

### 6.2 上传

- 把 `frontend/build` 全量上传到站点根目录 `/www/wwwroot/hao.uied.cn/`
- 把 `server/admin/dist` 上传到 `/www/wwwroot/hao.uied.cn/admin/`
- 把后端代码上传到 `/www/wwwroot/hao.uied.cn/server/`

## 7. Nginx 核心反代（必须有）

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8002/api/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

location /public/ {
    proxy_pass http://127.0.0.1:8002/public/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}

location /admin {
    alias /www/wwwroot/hao.uied.cn/admin;
    index index.html;
    try_files $uri $uri/ /admin/index.html;
}

location / {
    try_files $uri $uri/ /index.html;
}
```

## 8. 部署后自检（上线前必跑）

```bash
# API 健康检查
curl -i http://127.0.0.1:8002/api/site-info

# 线上 API 检查
curl -s https://你的域名/api/site-info

# 资源访问检查（图片）
curl -I https://你的域名/public/uploads/image/xxxx.png
```

预期结果：
- `/api/site-info` 返回 `code:0`
- `/public/uploads/...` 返回 `200`
- 前端首页与后台可打开，无 `502`

## 9. 升级发布建议（客户环境）

1. 先备份数据库。
2. 先传后端，再传前端/后台静态包。
3. 保留并备份 `server/app/public/uploads`（素材与上传文件）。
4. 重启后端服务。
5. 清浏览器缓存或强刷（`Ctrl/Cmd + Shift + R`）。

---

## 10. 常见问题速查

### Q1：前端接口全 502
- 看后端是否启动成功。
- 看 Nginx `/api` 反代端口是否与后端一致（例如 `8002`）。
- 看数据库连接是否报错（账号、密码、权限、host）。

### Q2：上传图片 URL 还是 localhost
- 检查后端是否运行在 prod 配置。
- 检查域名/反代是否正确传递 Host。
- 重启后端容器或进程，确认新配置生效。

### Q3：SEO 改了不生效
- 先确认 `/api/site-info` 返回值已更新。
- 再确认前端是否已部署新包。
- 搜索引擎结果存在抓取延迟，需等待重新抓取。
