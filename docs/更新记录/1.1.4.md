# UIED-NAV 1.1.4 更新记录

## 版本边界

- 版本号：`1.1.4`
- 发布类型：正式版
- 基线版本：`1.1.3`
- 本版主题：版本治理、生产 Docker 标准化、SEO 增量提交
- 数据库：当前改动不新增表、不删除表、不要求执行初始化 SQL

## 已完成

### 版本与交付

- 新增根目录 `VERSION`，作为客户包、部署脚本和发布体检的唯一版本源。
- 前台、管理后台、后端 `package.json` 与锁文件统一到 `1.1.4`。
- 后端接口显示版本改为读取后端 `package.json`，不再单独硬编码。
- 发布体检新增版本一致性检查，发现三端版本、更新记录或部署文档不一致时阻止发包。
- 客户包脚本在打包前强制执行发布体检，并禁止通过 `--version` 把 1.1.4 源码伪装成其他版本包名。
- 1.1.3 客户包和更新记录保持历史状态，不向旧版本继续追加 1.1.4 功能。

### Docker 生产部署

- 删除旧的 Prisma/SQLite/3001 Docker 启动方式，切换为当前 Egg.js/8002 后端。
- 新增生产镜像、Compose 配置和宝塔一键部署脚本。
- `npm ci --omit=dev` 只在镜像构建时执行，容器重启不再重复安装依赖。
- 上传、授权、日志均挂载到站点 `shared` 目录，升级源码和重建容器不会覆盖业务文件。
- 部署前自动备份官网、管理后台、旧容器配置和末尾日志，并记录最近备份路径。
- 容器增加健康检查和日志滚动，部署完成后校验授权公开状态与动态 Sitemap。
- 新容器启动或健康检查失败时自动恢复上一版 `uied-api`，成功后保留一个停止态回滚容器。
- 后端健康检查通过后才切换官网和后台静态文件；静态切换或 Nginx 参考配置生成失败时同时恢复前后台与后端。
- 自动兼容 Docker 20.10 之前不支持 `host-gateway` 的服务器，无法确认 bridge 网关时停止部署而不是使用错误配置。
- Compose 文件保留 `3.8` 格式以兼容宝塔常见的 `docker-compose v1`，正式构建前会先执行 `compose config` 预检。
- Docker 示例移除客户站签发密钥提示与数据库固定密码，可选 MySQL/Redis Compose 强制从环境变量读取密码。
- Docker 部署前校验站点域名、数据库与 Redis 地址；发现沿用 PM2 的 `127.0.0.1` 配置时主动停止并提示改用容器可访问地址。

### SEO

- Sitemap 静态路由的 `lastmod` 固定到当前服务版本启动时间，不再随每次请求变化。
- 站长平台首次运行优先提交最新内容，并使用“最新水位 + 历史回填水位”双游标：持续优先提交新更新，同时分批补齐全部历史 URL，超过单批上限也不会漏推。
- 百度、Bing 和 IndexNow 同时校验 HTTP 状态与业务错误字段，鉴权失败、整批 URL 被拒绝等响应不再误记成功，也不会推进增量游标。
- 没有新增或更新 URL 时自动任务正常跳过，不再报错或重复推送旧地址。
- 进阶 Sitemap 索引的分片 `lastmod` 跟随分片内最新内容，不再随请求时间变化。
- SEO 预渲染会把历史数据中的 `localhost`、`127.0.0.1` 等本机上传地址转换为当前正式站点资源地址，避免 `og:image` 和 JSON-LD 输出不可访问图片。
- 发布体检新增预渲染 HTML 本机地址扫描，发现任何本机 URL 时阻止发包。
- 新增生产 SEO 自检脚本，统一检查 robots、基础/进阶 Sitemap、首页 canonical、预渲染内链和未知详情 404。

## 本版不包含

- 不修改许可证签发算法、授权码数据或客户授权文件。
- 不自动提交百度站长平台 Token；管理员仍需在 SEO 中心填写站点和 Token。
- 不自动修改宝塔正在使用的 Nginx 配置；部署脚本只生成参考配置，应用前必须执行 `nginx -t`。
- 不自动导入数据库，不覆盖客户已有站点配置、文章、网址、订单或用户数据。

## 部署影响

- 新客户推荐使用 `scripts/deploy/docker/deploy.sh`。
- 旧 Docker 客户首次切换到 1.1.4 时会重建 `uied-api` 容器，数据库和 Redis 地址必须使用容器可访问地址。
- 旧 PM2 客户可以继续使用 `scripts/deploy/baota/deploy.sh`，两种运行方式不能同时占用 `8002`。
- 应将 Nginx 的 `/robots.txt`、`/sitemap.xml`、`/sitemap-advanced.xml` 和 `/sitemap-advanced/` 反向代理到 `127.0.0.1:8002`。

## 回滚

1. 查看最近备份：`cat /www/wwwroot/你的域名/shared/last-backup-path`。
2. 恢复备份目录中的 `web/` 和 `admin/`。
3. 根据 `uied-api.inspect.json` 确认旧镜像和挂载目录。
4. 回滚后检查：`curl -s http://127.0.0.1:8002/api/uied/license/public-status`。
