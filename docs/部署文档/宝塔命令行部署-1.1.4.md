# UIED-NAV 1.1.4 宝塔命令行部署

本版提供 Docker 和 PM2 两种生产方式。新客户推荐 Docker；已经稳定使用 PM2 的客户可以继续沿用。两种方式不能同时占用 `8002`。

## 1. 上传并解压

```bash
cd /www/wwwroot/hao.uied.cn
mkdir -p source/releases/1.1.4
tar -xzf uied-nav-1.1.4-customer-source.tgz \
  --strip-components=1 \
  -C source/releases/1.1.4
cd source/releases/1.1.4
```

校验版本：

```bash
cat VERSION
node -p "require('./server/server/package.json').version"
```

两条命令都必须输出 `1.1.4`。

## 2. 推荐方案：Docker 统一入口

```bash
chmod +x scripts/deploy/docker/deploy.sh
./scripts/deploy/docker/deploy.sh --domain hao.uied.cn
```

脚本自动判断部署模式：

1. 已存在运行中的 `uied-api`，并且 `/app` 已挂载到宿主机：自动原地安全升级。
2. 不存在 `uied-api`：进入全新 Docker 安装。
3. 明确需要重建现有容器：增加 `--rebuild`。

### 2.1 已有 uied-api 原地升级

已有容器直接执行统一命令即可，不需要重新填写数据库配置，不拉 Node 基础镜像，不执行 `npm install` 或 `npm ci`。

脚本会自动完成：

1. 从容器挂载信息确认正式后端目录，拒绝修改未持久化的容器层。
2. 比较新旧生产依赖；依赖变化时在修改线上文件前停止。
3. 备份当前 `web`、`admin`、后端源码、容器信息和末尾日志。
4. 保留现有 `node_modules`、`.env`、生产配置、授权、日志、导出文件和上传目录。
5. 更新后端并重启现有 `uied-api`，检查授权公开接口与动态 Sitemap。
6. 后端通过后切换预构建官网和管理后台；任一步失败自动恢复本次备份。

正式升级前可预检：

```bash
./scripts/deploy/docker/deploy.sh --domain hao.uied.cn --check-config
```

预检通过时会显示：

```text
原地升级检查通过：v1.1.4，不重建镜像、不安装依赖。
```

### 2.2 全新 Docker 安装

全新环境首次运行会生成：

```text
/www/wwwroot/hao.uied.cn/shared/uied-api.env
```

填写数据库账号、密码、数据库名后，再执行同一条部署命令。宝塔宿主机上的 MySQL 和 Redis 默认通过 `host.docker.internal` 访问。

填写后可只检查配置：

```bash
./scripts/deploy/docker/deploy.sh --domain hao.uied.cn --check-config
```

全新安装会自动完成：

1. 备份当前 `web`、`admin` 和旧容器信息。
2. 构建 `uied-nav-api:1.1.4` 镜像并重建 `uied-api`。
3. 挂载 `shared/uploads`、`shared/licenses` 和 `shared/logs`。
4. 等待容器健康并检查授权公开接口与动态 Sitemap。
5. 后端验证通过后同步预构建官网与管理后台，保留 `web/.user.ini`。
6. 生成 `deploy/uied-nav.nginx.conf` 参考配置。

新容器启动、健康检查或静态文件切换失败时，脚本会自动恢复上一版 `uied-api` 和本次部署前的静态文件。部署成功后上一版容器会以 `uied-api-rollback` 停止态保留，下一次成功升级时替换。

Docker 20.10 及以上自动使用 `host-gateway`；旧版 Docker 会自动读取默认 bridge 网关。无法读取时脚本会中止，不会带着错误的数据库地址启动容器。

已有容器确实需要切换到标准镜像时执行：

```bash
./scripts/deploy/docker/deploy.sh --domain hao.uied.cn --rebuild
```

`--rebuild` 属于维护操作，需要可访问的 Docker 基础镜像源，并要求提前完成 `shared` 配置与运行时数据迁移。日常版本升级不需要使用。

依赖只在镜像构建时安装。以后执行：

```bash
docker restart uied-api
```

不会再次运行 `npm install` 或 `npm ci`。

## 3. 兼容方案：PM2 部署

```bash
chmod +x scripts/deploy/baota/*.sh
./scripts/deploy/baota/deploy.sh \
  --domain hao.uied.cn \
  --site-root /www/wwwroot/hao.uied.cn
```

首次运行同样会生成 `shared/uied-api.env`。填写后再次执行。PM2 方式会在明确部署时安装生产依赖，但服务重启不会重复安装。

## 4. 新客户初始化数据库

只有全新空数据库允许执行：

```bash
./scripts/deploy/baota/init-database.sh \
  --env /www/wwwroot/hao.uied.cn/shared/uied-api.env \
  --confirm-new-database
```

老客户升级到 1.1.4 禁止执行本步骤。本版没有强制数据库补丁。

## 5. Nginx

部署脚本生成的参考配置位于：

```text
/www/wwwroot/hao.uied.cn/deploy/uied-nav.nginx.conf
```

宝塔已有站点配置时不要直接覆盖整个 `server {}`，只核对并合并 API、后台、SEO 文件和预渲染详情路由。必须确认以下地址由后端动态响应：

```text
/robots.txt
/sitemap.xml
/sitemap-advanced.xml
/sitemap-advanced/*.xml
```

应用前执行：

```bash
nginx -t && /etc/init.d/nginx reload
```

## 6. 授权与持久化目录

```text
/www/wwwroot/hao.uied.cn/shared/uied-api.env
/www/wwwroot/hao.uied.cn/shared/uploads
/www/wwwroot/hao.uied.cn/shared/licenses
/www/wwwroot/hao.uied.cn/shared/logs
```

客户站必须保持：

```env
UIED_ENABLE_LOCAL_LICENSE_SIGN=false
```

客户站不要配置 `UIED_LICENSE_SIGN_SECRET` 或 `UIED_LICENSE_API_SIGN_SECRET`。

## 7. 验收

```bash
docker ps --filter name=uied-api
docker inspect -f '{{.State.Health.Status}}' uied-api
curl -s http://127.0.0.1:8002/api/uied/license/public-status
bash scripts/deploy/verify-production-seo.sh https://hao.uied.cn
```

Docker 日志：

```bash
docker logs --tail 100 uied-api
```

## 8. 备份与回滚

最近一次备份路径：

```bash
cat /www/wwwroot/hao.uied.cn/shared/last-backup-path
```

Docker 脚本和原地升级的文件备份默认在：

```text
/www/backup/hao.uied.cn/时间-v1.1.4/
```

原地升级备份目录带有 `-in-place` 后缀。

数据库仍需在升级前单独备份：

```bash
mysqldump --single-transaction -u数据库账号 -p 数据库名 \
  > /www/backup/hao.uied.cn/database-before-1.1.4.sql
```

## 9. SEO 平台配置

部署成功后进入后台 SEO 中心：

```text
/admin/system-setting/base-config/seo-center-config
```

至少完成：

1. 填写百度站点验证内容。
2. 配置百度推送的站点地址和 Token。
3. 开启自动任务与站长推送任务。
4. 手动执行一次 Sitemap 和站长推送，确认日志成功。
